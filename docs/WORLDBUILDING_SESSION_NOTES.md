# Worldbuilding session notes (2026-11-19)

First real prep session with Atlas: world → region → town → site/dungeon → interior, shown on the player screen with fog.

Each snag: **what you tried → what happened → what you expected.** Severity: **block** (stopped us), **hurt** (slowed us / confused), **nit**.

## What we're building

Grim Tides, from the vault at `D:\Grim Tides` (read-only):

- **World:** Etharis, from the vault's own map picture (`World/image.png`, 2670×4096, no labels): backdrop → trace → terrain detail.
- **Region:** Castinellan Provinces: the Arcanist Inquisition's peninsula, where arcane magic is illegal.
- **Town:** Ember Cairn: the dragonborn ancestral home and seat of the Seraph faith.
- **Interior:** Cathedral of Embers.
- **Dungeon:** Ash Hollow, the anti-magic prison under the cathedral (Warden Crill, hidden tunnel, chalice riddle → Seraphine Deymar's tomb in the Forgotten Labyrinth).

## Snags

1. **hurt (known before starting): no "under this building" link.** The prison is beneath the cathedral. Atlas can make the cathedral an interior of its building, but a dungeon can't be attached as that building's lower level. Workaround: Ash Hollow becomes its own site map under Ember Cairn. Expected: a building's interior could have floors/levels, or a dungeon could hang off a building or interior.
2. **block: Import Backdrop Image failed:** "Error invoking remote method 'atlas:asset-import-image': Error: Cannot read this image. Choose a PNG, JPEG, WebP or BMP file." The raw IPC wrapper text shows in the UI. Import uses Electron `nativeImage.createFromPath` (`src/main/ipc.ts:357`). I checked that both the vault's `World/image.png` (2670×4096 PNG) and the labeled Etharis JPG decode fine through `nativeImage`, so the failing file was something else. Suspect a WebP: `nativeImage` doesn't decode WebP on Windows, yet the message lists WebP as supported. Expected: any format the message names actually imports; a clean error message without the "Error invoking remote method" prefix.
3. **nit:** the top bar says **New** / **Open**, the guide says "New World" / "Open World". The world is always created as "New World", with no prompt for a name.
4. **hurt (scale):** the labeled Etharis map uses 20-mile grid squares, measured at 20 px each, so 1 mi/px and about 1000 mi wide. The clean `image.png` shows the same land at about 900 mi wide. The vault's Leaflet note says 200–250 mi, off by 4×. Atlas asks for a real width with no way to read it off the map's own scale bar, except the separate Set Real Size calibration. Fine, but easy to get wrong silently.
5. **hurt: the first trace calls the whole map land (1.3% water).** The auto-detect only treats *blue* pixels as sea (`import/trace.ts:80-92`). Etharis has a dark grey-green painted sea, so it found a few blue specks at the bottom edge and nothing else. The dialog opens on "Paint water" and doesn't say "sample the sea first" when the result is obviously wrong. Expected: auto-detect uses the dominant border colour whatever its hue, or the dialog prompts for a sample when water < ~10%.
6. **hurt: sampling the sea can't separate a painted map.** After sampling: "45 land regions · 171 lakes · 5 river paths · 18.9% water". The dark forest canopy matched the sea colour and became ~170 fake lakes. The sea is a gradient (navy at the bottom, grey-green up top, a pale glow at the coast), so one sampled colour only caught part of it, and the coastal glow stayed land. Rivers never trace: they're pale lines, nothing like the sampled dark sea, and the tracer only finds rivers as thin strips of "water" colour. Workaround: hand-paint the mask with a big brush. Expected for painted maps: several water samples (click 2–3 spots), a "connected to the map edge" sea fill (flood from the border instead of matching colour everywhere, which would kill the forest lakes), and a separate river colour sample.
7. **hurt: can't see the coast under the trace tint for touch-ups.** The land/water tint has a fixed opacity (alpha 85, `TraceGeographyDialog.tsx:45`), and the preview has no zoom (max 65vh tall). Fine coastline corrections are guesswork. Wanted: a tint opacity slider (or an outline-only view showing just the land/water edge), plus zoom/pan in the preview. The opacity slider is a ~5-line change. **Fixed mid-session:** Tint slider (0–80%) and Zoom (Fit/2×/3×/4×, scrolls inside the dialog) added to Trace Geography.
8. **block: the whole window went white while painting the trace mask.** The renderer process died; the main process and GPU process were still running, and nothing reloaded the page, so all the painting was lost. Likely cause: every brush move created a new full-size canvas plus a 3.75 MB ImageData for the tint (`TraceGeographyDialog.tsx`, redraw effect). The native canvas memory piled up faster than GC freed it during long brush-100 strokes. **Fixed mid-session:** the tint canvas/buffer is reused, and the main window now logs `render-process-gone` and reloads instead of sitting white (`src/main/index.ts`). Not yet proven: the OOM cause is inferred, not reproduced. If it whites out again, the log line names the reason. Still missing: trace-mask painting isn't saved anywhere, so any crash or Cancel loses it all.
   - **Happened again after the buffer fix:** this time the reload kicked in, but it came back with *no world open*, so the leak fix didn't cover the real cause. Added: the crash reason plus per-process memory is written to `%APPDATA%\campaign-atlas\renderer-crashes.log`, and after a crash-reload the window reopens the world that was open (`atlas:current-world-dir`). Cause still unknown; watching renderer memory while painting.
9. **block: fog brush on the world map ate 4.5 GB and crashed the app.** The renderer went from 90 MB to 4.5 GB in ~30 s, then: "Unable to find segment #60942 … in SweepLine tree" from polygon-clipping inside `paintFog`, and the whole app was replaced by the error screen. Cause: the fog brush radius is in metres (default 3 m) on a 1,609 km-wide world. A drag pushed a point every 0.75 m of travel, i.e. one per mouse event, so thousands of microscopic circles were unioned at ~1e6-metre coordinates. Near-duplicate vertices broke the sweep line. Probably also the real cause of crash #8 (trace accepted fine; the world shows 12 traced land areas). **Fixed mid-session:** the fog brush is never smaller than ~12 screen pixels (`tools/fogTool.ts`); `paintFog` drops points closer than half a radius and catches merge failures, skipping that stroke instead of crashing (`geom/fog.ts`). Checked: three overlapping 400-point strokes at world coordinates merge in 59 ms. Still wrong: "Brush radius (m)" in Player & fog means nothing at world scale; it should be in screen pixels or scale with the map.
10. **hurt: Open always starts in Downloads.** Every reopen means navigating to the world folder again. The main process already keeps `recent-worlds.json` (`readRecentWorlds`, `atlas:world-recent-list`), but nothing in the UI uses it, and the folder picker gets no `defaultPath`. Expected: Open starts at the last world, or a Recent list, or the last world reopens at launch.
11. **hurt: accepted trace buries the painting.** After Accept Geography the world map shows a flat beige land blob with blue coast ripples on top of the Etharis painting. All the art (forests, mountains, rivers) is hidden, the coast is coarse (the hand-painted mask was at 782 px across the map, ~2 km per pixel), and big water-ripple circles sit on Castinella where water was brush-painted. Expected: on a world traced from a painting, the painting stays the visible map and the traced shapes sit invisibly underneath as geography for child maps. There's no image opacity or "show backdrop on top" control. Workaround: a new layer above Base, with the backdrop moved onto it (Layers + Inspector "Move to layer").
12. **block: zooming in on the world map crashed (renderer OOM, three times in a row).** `renderer-crashes.log`: "renderer gone: oom". Just *opening* Etharis took the renderer from 100 MB to 1.75 GB (2 GB JS heap). A heap sample showed it all in Pixi's `buildLine → round` and `buildSimpleUvs`. Pixi makes a round join/cap from `15·angle·√radius/π` segments with the radius in local units. Map graphics are in metres, and on a world map the screen-sized strokes (`width ∝ 1/zoom`, e.g. the 4 coastal-glow strokes at `strokeUnit*44`) are ~75 km wide, so ~1,400 segments per coastline corner. Zooming rebuilds everything while the old copy is still alive → OOM. Probably behind crash #8 too. **Fixed mid-session:** `render/strokeGuard.ts` turns round joins/caps into bevel/butt for any stroke wider than 128 map units (installed from `drawEntity.ts`, so it covers the editor, PNG export and the player view). Measured on the live app: Etharis opens at 234 MB (was 1.75 GB), and 70 wheel-zoom steps peak around 560 MB with no crash. Visual cost: slightly pointier glow at the sharpest coast corners.
13. **hurt (lost work): bumping Sensitivity after careful hand-painting wiped it all.** Changing Sensitivity or the water sample re-ran detection from scratch *and* cleared the correction undo stack, so the hand-painted coast was gone with no way back. **Fixed mid-session:** the current mask goes onto the undo stack first, so **Undo correction** (Ctrl+Z) brings it back. Still a trap: the slider sits right next to the brush controls, and nothing warns that it repaints everything.
14. **hurt: re-tracing adds instead of replacing.** `map.applyTrace` adds a new "Traced geography" group and leaves the previous one alone. Land is the union of all land areas, so a carefully refined coast is still buried under the coarse first attempt unless you delete the old group by hand first. Expected: re-trace from the same backdrop offers "replace previous trace".
15. **wanted: a fill tool for land borders.** The workflow the user came up with on their own: paint the coastline as a *border* of land with the main-map **Paint land** brush, tracing the painting's coast, then fill the middle. That worked well for blocking out Castinella. Missing piece: a bucket fill ("make everything inside this border land") for the main-map land/water brushes and for the trace mask. Today you have to brush the whole interior by hand.
16. **hurt (silent): a painted border leaves holes that count as water.** The border strokes merged into the traced land and closed off 20 pockets between the new coast and the old blob. They became *holes* in the land shape (about 27,000 sq mi in total, all inside Castinella), so per the geography rules they're water: inland lakes where the user meant land. On screen they just look like the painting showing through, so nothing says "this is water now". Expected: a fill tool (#15), or at least a different look for holes, or a "fill holes" action on a land area.
17. **block (for rivers): no way to see the backdrop through map shapes.** I misread the first opacity request (#7) as being about the trace dialog. What the user needed is the painting visible *under* the land/water shapes on the main map, so they can hand-trace coasts and later rivers against it. Once land covers the painting, rivers can't be traced at all. **Fixed mid-session:** each row in **Layers** has a see-through slider (10–100%). It's editor-only: not saved in the world, not shown on the player screen, remembered on this computer.
18. **hurt: "Populate POIs & detail" writes generic fantasy over an existing setting.** The Castinella region (514×457 mi) came out good-looking, with coast, rivers, hills, mountains and roads, plus 10 settlements, 26 Places, 5 factions and hooks. None of it knows the campaign: invented names (Caldmoor, Wynford, Lorstead…) where Toletum/Faro/Therpena/Ember Cairn should be, invented factions ("Blackwater Compact", "Hearthstone Barony") in the Arcanist Inquisition's theocracy, and cosy hooks ("known for horse fairs"). It also put **29 rainforest patches** on what the painting shows as a harsh, arid, orange-brown peninsula. Expected: a populate option that keeps terrain detail but skips named places, or takes the existing names/tone; biome from the backdrop's colours (or the parent's) instead of latitude guesses. Some hooks do fit by luck: "Wynford: a famous shrine; the bells ring by themselves at night", "Lorstead: a witch-hunter has arrived".
19. **hurt: child maps always draw inside their parent, with no off switch.** Zooming out on Etharis showed the whole Castinella region as an opaque box (its own ocean, labels and 400-odd symbols) pasted over the world painting. Any child bigger than 64 px on screen draws inline (`MapView.tsx`, "Draw inline child maps"). It's also rebuilt from scratch on every scene sync. **Fixed mid-session:** a **Child maps** checkbox in the top bar next to Zoom-through (view-only, remembered on this computer). Still worth doing: draw the child's contents without its own ocean/backdrop, so it blends into the parent instead of covering it.
20. **hurt (looks): world/region coast glow.** The halo is a fixed ~37 px on screen, so at full-map view every small island became a fat bullseye blob. After the #12 memory fix, the wide glow strokes also got spiky triangle corners. **Fixed mid-session:** the glow is drawn in screen-pixel units (coords × zoom, Graphics scaled back), so round joins are cheap and smooth again. Its width shrinks on landmasses under ~90 px on screen, and it now sits under the land fill (water side only) instead of washing over the land edge. Checked by rendering both the Etharis world and the Castinella region.
   - **Fixed (#10):** folder pickers now start at the last world. Open lands on the last world folder; New/fork/target pickers open its parent folder (`atlas:pick-folder`).
