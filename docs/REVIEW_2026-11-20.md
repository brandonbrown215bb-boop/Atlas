## Fix first — crashes and lost work

**R1. The map view leaks every drawing it throws away.** *checked against Pixi source*
`render/MapView.tsx` — every `destroy({ children: true })` (355, 370, 378, 448, 473, 494, 517, 621, 677).
Pixi only frees a Graphics' geometry when you pass `context: true` (or nothing). With `{children:true}` the geometry sits around until Pixi's GC sweeps it, 60–90 s later. Meanwhile child previews, place badges, road overlays, fog and the full-map grid are rebuilt on *every pan pointermove* (AUDIT #16, still open), and wheel zoom syncs the scene twice. This is the most likely remaining cause of the world-map OOM crashes.
Fix: `{ children: true, context: true }` everywhere (not `true` — that also kills shared textures). Then: grid only over the viewport, single sync on wheel.

> **✅ Fixed.** All `MapView.tsx` destroys now pass `context: true`, including the app teardown. Nothing in the code shares a GraphicsContext, so this is safe. The grid draws only the lines on screen. Wheel zoom rebuilds the scene once per step instead of twice. Inline child-map previews (Castinella inside Etharis) are cached and rebuilt only when the child map, the zoom level (by more than 25%), the roof mode or its textures change, not on every pan step. Measured: panning alone stays flat (GPU 324 → 244 MB over 8 rounds).

**R1b. (New, found while testing R1) The coast glow from `c7e4f4c` was the main memory hog.** *proven*
`render/drawEntity.ts`, the world/region coast glow. Last night's change drew the glow in screen pixels with round joins, but a traced coast has many points per screen pixel. Each point got a round join on all 4 glow strokes, so Etharis's two coasts came to **~772k and ~684k vertices**, rebuilt on every zoom step. Pixi keeps the old buffers in a pool sized to the largest geometry it has ever held, so memory ratcheted up and never came back. Zooming alone took the heap from 127 MB to 1.3 GB in 26 s.

> **✅ Fixed.** The glow outline is thinned to one point per ~1.5 screen pixels before stroking. It's a soft glow, so the difference is invisible. The coast glow went from 772k to 72k vertices, and the heap at open from 123 MB to 74 MB. This is the fix that stopped the crash in the before/after table.

**R2. Dashed GM zone outlines explode at deep zoom.** *checked*
`render/drawEntity.ts:367-375`. Frontier/faction/rumor dash length is `strokeUnit*8` = screen-sized, no floor, no clipping. A 125 km faction zone zoomed to 1 px/m is ~35k round-capped dashes per zone. Zoom in on a populated region → OOM.
Fix: floor the dash at `perimeter / 1500`, or draw them solid.

> **✅ Fixed** in `drawDashedPolyline` (`drawPrimitives.ts`). A dashed line never has more than 1,500 dashes. When zoomed way in, the dash and the gap stretch together instead of multiplying. This covers every dashed line, not just zones. It isn't covered by the live test, because Etharis has no faction zones yet.

**R3. Crash → reload → reopen → crash, forever, and it eats your backups doing it.** *checked*
`main/index.ts:213` reloads the dead renderer, `App.tsx` reopens the same world. A world that OOMs on open loops. Worse, every open makes a backup (`worldFs.ts:217`) and only 20 are kept, so 20 loops replace every good backup with the crashing state.
Fix: if the renderer dies twice within a minute, reload without reopening.

> **✅ Fixed, checked live.** Two renderer crashes within 60 s: the window reloads with no world open and shows a "crashed again" message pointing at `renderer-crashes.log` (`main/index.ts`). Reopen is switched off through `setReopenAfterCrash` in `ipc.ts` and switched back on when you open a world yourself. A single crash still reopens the world as before. R4 (transfers making extra backups) is separate and still open.

**R4. Backups get pushed out by transfers.** *proven (0 → 6 backups from one copy)*
`transferFs.ts:18,29,46,66` read worlds through `openWorldFolder`, which backs up every time. Picking a target + one copy = 6 backups in the target; 3–4 transfers wipe its restore history.
Fix: a read-only `readWorldFolder` for transfers/verification; only back up on a real open.

**R5. The "Atlas hit an error" screen turns off autosave and save-on-close.** *checked*
`App.tsx:96-101` starts persistence inside App. When App crashes the error boundary unmounts it, the cleanup cancels the pending save and removes the close-flush hook. Close the window → everything since the last autosave is gone (usually including the edit that crashed). The agent bridge dies too.
Fix: start persistence and the agent bridge in `main.tsx`, outside React.

> **✅ Fixed, checked live.** `startWorldPersistence()` and `startAgentBridge()` now run once in `main.tsx`, so the error screen can't stop them. This also means they no longer start twice under StrictMode in dev.

**R6. New World on an existing world's folder overwrites it.** *proven*
`worldFs.ts:110` never checks. Name → "New World", map list → just map-1, assets index → `{}`, other map files orphaned, no backup. The folder picker now opens next to your last world, which makes this easy to do.
Fix: refuse if `world.json` exists (fork already does this check).

**R7. Autosave can be postponed forever.** *checked*
`persistence.ts:57-79` restarts the 2 s timer on every store change. Steady painting or an agent sending a command every second never pauses 2 s; the only forced save is the 10-minute backup. Combine with an OOM → up to 10 minutes lost.
Fix: if dirty for 10 s, save now instead of rescheduling.

> **✅ Fixed, checked live and by unit test.** `MAX_UNSAVED_MS = 10_000` in `persistence.ts`. A new test in `persistence.test.ts` edits every second for 12 s and expects a save; it fails without the fix.

**R8. Closing while typing loses the text.** *traced*
Inspector/Places text fields commit on blur/Enter. The close flush doesn't blur, so a half-written GM note isn't saved.
Fix: `document.activeElement?.blur()` before the flush (and in popouts).

> **✅ Fixed for the main window**, but not checked live. Both the close flush and `beforeunload` now blur the focused field first, which commits it. **Still open:** a field you're typing in inside a *popped-out* panel isn't blurred on close.

**R9. "Pull from parent" damages child maps.** *proven (all five)*
`model/commands.ts` ~1173-1258, `geom/clipInherit.ts`. Inherited entities get new random ids on every pull, and several commands don't account for that:
- Generated interior: the footprint is rebuilt without `usage:'boundary'`/`groupId` → it draws **over the rooms**.
- Interior opened from an inherited Place: the place is recreated without `childMapId` → the interior is orphaned.
- A Place you made on an inherited icon → its link points at a dead id.
- Things you deleted from the child **come back**.
- Pull replaces the child's whole `terrain` record, deleting its own generated elevation.
Fix: give inherited copies stable ids (`inh:<parentId>`), set `origin:'manual'` when you link/open/place on an inherited entity, keep tombstones for deleted inherited ids, merge terrain instead of replacing.

**R10. Restore latest backup overwrites every map with no safety copy.** *traced*
`App.tsx:301`, `worldFs.ts:248`. One damaged map → open fails → restore rewrites all the healthy maps too. Also leaves the old asset index loaded (images missing until reopen).
Fix: `createBackup` before restoring; load the assets index after.

**R11. Two copies of Atlas can run on the same world.** *checked*
No `requestSingleInstanceLock`. Last save wins; the agent keeps talking to the first instance.
Fix: single-instance lock, focus the existing window.

**R12. Ctrl+R reloads the editor; Ctrl+-/= zoom the whole UI.** *checked*
`main/index.ts:247` uses the default `viewMenu`. Reload drops undo history and any open dialog (e.g. trace-mask painting) and adds another backup.
Fix: explicit View menu without reload/zoom (devtools in dev only).

## Wrong results you'll notice

- **See-through slider bleeds across maps.** *checked* — `layerOpacity` keyed by layer id, and every map's first layer is `layer-base`. Key by `mapId:layerId`.
- **Camera snaps back to the last focused Place after every edit.** *checked* — `MapView.tsx:1259` never clears `focusPlaceRequest` and re-runs on every map change. Clear it after use.
- **Clicking picks the wrong thing.** *proven* — `geom/hitTest.ts:269` picks by insertion order, not draw order. Click a town icon → you get the road under it, or land painted later. Walk `geographicEntities()` in reverse.
- **Labels can't be clicked (or vanish at screen edges) on world/region maps.** *proven* — label hit box is ~0.4 m per char, left-anchored; labels are drawn centred at screen size.
- **Zoom-through mid-stroke paints onto the other map.** *traced* — land/water/fog brushes and select drags aren't reset on map switch, and wheel doesn't check for an active drag. Scroll out mid-stroke → region coords painted on the world.
- **Hidden sewers can be selected and deleted.** *traced* — renderer hides them, hit-test doesn't. Box-select a district + Delete takes the invisible sewers too.
- **Trace dialog: removing a river, then painting, removes a different river.** *checked* — `removed` holds indices, rivers are recomputed after each stroke.
- **Trace Geography / Set Real Size always use the first image on the map,** not the selected one. *checked* — `MapsPanel.tsx:50`. Matters when you've imported both Etharis images.
- **Colour picker floods undo.** *checked* — every drag step is its own undo entry; 200-entry cap → dragging the picker erases your undo history.
- **Reroll dressing deletes cave features and never puts them back.** *proven* — footbridge, campfire, stalagmites, boulders, shrine, pillars, story trap; their lights stay glowing on nothing. `framework.ts:40` treats every non-`feature` prop as dressing.
- **Building interiors fail ~28% of seeds on non-grid sizes.** *proven* — 60×40 m: 17/60 seeds throw "No clear entrance fits"; grid-snapped size: 0/60. `dungeon/layout.ts:361/735`.
- **Negative seeds crash cave and chamber.** *proven* — `(seed + n*5) % 6` goes negative. Use `seed >>> 0`.
- **Undo after a Move/Linked transfer only undoes this world.** *traced* — the other world's files are already written; after undoing a Move the map exists in both.
- **Stale drawings after geography edits.** *traced* — render cache keys on `rev`, but clipped biomes/lake holes change without a rev bump. Ghost shapes until the next zoom step.
- **"Parent changed" is stuck on for settlements/sites developed over an icon,** and for interiors whose building was deleted (Pull then always errors). *proven / traced*
- **GM-only lights light the room in the player view.** *traced* — `lighting.ts` ignores layer visibility and GM-only.
